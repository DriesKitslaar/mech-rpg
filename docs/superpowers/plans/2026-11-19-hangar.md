# The Hangar Implementation Plan

**Goal:** Seven places for a saved build where there were three, each listed in the garage by the class of the build kept there; a game kept with three loads as it was.

**Architecture:** `LOADOUT_SLOTS` goes from three to seven. The list of saved builds in a kept game may be shorter than that (a game from before): the validity check takes three to seven places, the storage brings a shorter list to full length on loading, and the rules that write a place write the full list. Everything that turns through saved builds takes its number from the list already; the range's ids for sparring partners take theirs from `LOADOUT_SLOTS`.

**Tech Stack:** TypeScript, Canvas 2D, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-hangar-design.md`

## Global Constraints

- No rule of combat changes and no balance test changes.
- A kept game loads and is as it was; the save version does not change.
- Every new English text has its Dutch, inside the room its kind has; an interface string in Dutch is at most two letters longer than the English.
- Nothing is merged without the user's word.

## Review Focus

- A game kept with three places, one of them filled: loads, shows seven rows, the filled one where it was, and can be saved into the seventh.
- A list of two places, of eight, or with something that is no build in the seventh: refused.
- The seventh place: saved to in the garage, turned to at the briefing, flown from, and sparred with on the range, by its own number everywhere.
- Seven builds saved, in Dutch: the garage's list, the briefing's header with `(BUILD 7)`, and the range's list fit.
- A place past what a short list names: reads as empty and is not an error anywhere (the range, the briefing, the garage).

### Task G1: seven places

**Files:** `src/core/game.ts`, `src/core/range.ts`, `src/platform/storage.ts`, `src/ui/garageFlow.ts`, `src/ui/garageScreen.ts`, `src/content/strings.ts`, `src/content/nl/*`, `src/content/codex.ts`, tests beside each, `e2e/hangar.spec.ts`, `docs/handleiding.md`, `README.md`

**Interfaces:**

- `LOADOUT_SLOTS = 7`; `LOADOUT_SLOTS_MIN = 3`: the fewest places a kept game may name.
- `saveLoadout` and `clearLoadout` write a list of `LOADOUT_SLOTS` places whatever length they were given; `checkLoadout` reads a place the list does not name as empty.
- `isValidState`: a list of `LOADOUT_SLOTS_MIN` to `LOADOUT_SLOTS` places.
- Storage: a kept game with a shorter list is given empty places up to `LOADOUT_SLOTS` on loading.
- `parseSpar(id)`: a place from 0 to `LOADOUT_SLOTS - 1`.
- `GarageFlow.loadoutItems()`: `LOADOUT_SLOTS` rows; a filled row is `<n>  <class>` with the first word of its core's name as the note.
